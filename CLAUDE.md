# Как обновлять сайт

Статический сайт на GitHub Pages (домен ainewstobeinformed.ru, файл CNAME не трогать).
Требования к новостям — в RULES.md, их нужно прочитать перед сбором.

## Устройство
- `index.html` — весь сайт. Структура адресов:
  `#/` главная (Статистика / Аналитика) → `#/stats` (Новости, Отчеты компаний и рынков, Курсы валют,
  Макроэкономика, Цены, Интересные статьи; список — массив `STATS`) → `#/stats/fx` — курсы валют (см. ниже); остальные `#/stats/<id>` — заглушка
  «Информация появится позже»; `#/analytics` — заглушка.
  Раздел «Новости» — `#/news`: выбор периода → категории → подкатегории → новости (`#/news/p/...`),
  источники — `#/news/sources`. Старые адреса `#/p/...` и `#/sources` перенаправляются туда же.
  Данные грузит из `data/`.
  На каждом экране есть поиск по словам, только внутри текущего этапа: архив → период → категория → подкатегория
  (функции `searchBlock`/`bindSearch`; запрос сохраняется в адресе как `?q=`).
- `data/categories.json` — дерево категорий (`"subs": "countries"` = подкатегории-страны из списка `countries`).
- `data/days/YYYY-MM-DD.json` — новости за день; день = дата публикации новости в источнике.
- `data/manifest.json` — список дней и количество новостей (генерируется скриптом).
- `data/sources.json` и `SOURCES.md` — список источников: группа → сайт → раздел (ссылки на сайты и разделы,
  не на новости). Генерируются `tools/sources.py`; на сайте — страница «Новостные источники» (`#/sources`).
- `tools/sources_map.json` — справочник для источников: группа и название каждого домена (`sites`),
  разделы сайта по началу пути ссылки (`sections`), рубрики RG по подкатегории (`rg_by_sub`).

## Курсы валют (`#/stats/fx`, код — `fx.js`)
- `data/fx/USDRUB.csv`, `EURRUB.csv`, `EURUSD.csv` — дневные цены Investing.com (date,close,open,high,low);
  `data/fx/manifest.json` — диапазоны дат. Другие пары (RUB/USD, USD/EUR…) сайт считает как обратные.
- Обновление базы за период (данные ДОПИСЫВАЮТСЯ, старое не удаляется) — через GitHub Actions,
  т.к. Investing.com из среды Claude недоступен:
  `gh api -X POST repos/neimanr22-netizen/ainewstobeinformed/actions/workflows/fx.yml/dispatches -f ref=main -f 'inputs[start]=ГГГГ-ММ-ДД' -f 'inputs[end]=ГГГГ-ММ-ДД'`
  затем проверить запуск (`gh api 'repos/.../actions/runs?per_page=1'`) и сделать `git pull`.
  Скрипт — `tools/fx_fetch.py` (api.investing.com, запасной путь — tvc.investing.com).
- `data/fx/forecasts.json` — прогнозы аналитиков по USD/RUB (организация, горизонт, значение, дата, ссылка).
  Обновлять поиском свежих публикаций; старые прогнозы той же организации заменять новыми.
- При открытии страницы автоматически подгружаются онлайн-курсы (currency-api / open.er-api.com), официальный курс ЦБ
  (cbr-xml-daily.ru). Кнопки «Обновить» нет (убрана по просьбе владельца).

## Порядок обновления
1. Посмотреть, чего не хватает: `python3 tools/stats.py 2026-11-01 2026-11-14 10`
2. Собирать новости по одной (под)категории за раз, складывать в batch-файл вне репозитория
   (JSON-массив: date, cat, sub, title, summary, url, source — см. tools/add_news.py).
   **Порядок отсмотра (требование владельца — ничего не упускать):**
   a. `python3 tools/sources.py --for CAT SUB` — список известных источников рубрики.
   b. Отсмотреть ВСЕ источники из списка 1 за весь период: ленту/раздел (WebFetch), архив по дням,
      если есть, или WebSearch с allowed_domains [домен] и датами. Затем — список 2.
   c. Только потом искать новые источники: местный язык, mode="extended", официальные сайты
      (статистика, правительство, ЦБ), пресс-центры компаний, отраслевые издания.
   d. Из всего найденного выбрать самые полезные, без повторов одного события.
   e. В отчёте владельцу: какие известные источники отсмотрены, какие не открылись, какие новые добавлены.
3. Добавить: `python3 tools/add_news.py путь/к/batch.json` — скрипт проверит поля, отбросит повторы
   и сам пересоберёт список источников. Если он пишет «Нет в tools/sources_map.json», добавить новые домены
   в `sites` (группа + понятное название; группы — в `groups`), а если раздел виден в адресе ссылки —
   в `sections`; затем `python3 tools/sources.py`. Пресс-релизы на сайте компании → группа «Сайты компаний».
4. Коммитить и пушить в `main` после каждой категории, чтобы прогресс не терялся.
   Сайт обновляется через 1–2 минуты после пуша.

## Практические советы по поиску
- RG.ru хорошо находится обычным WebSearch с allowed_domains ["rg.ru"] — в выдаче есть текст и дата.
- РБК: поиск почти не индексирует свежие статьи; через WebFetch доступны только текущие ленты
  (rbc.ru/economics/, rbc.ru/rubric/politics) — это последние 1–2 дня. Статьи открывать по точному URL
  из ленты (вместе с ?from=...), иначе WebFetch откажет. Дату брать из URL.
- Зарубежные новости 2026 года лучше искать в режиме mode="extended" и на местном языке
  (нем., чеш., слов., венг.) — стандартный поиск часто отдаёт материалы 2025 года.
- У RG.ru есть архив по дням: rg.ru/date/YYYY/MM/DD (заголовки, ссылки, рубрики). Напрямую по
  собранному вручную адресу WebFetch не пускает — сначала найти страницу поиском
  (запрос вида «Новости России и мира за 2 октября 2026»), потом открыть её и статьи из неё.
- Для отраслевых новостей России удобны new-retail.ru и retail.ru (в выдаче поиска есть дата и текст).
- Ежедневный сбор надёжнее, чем раз в две недели.

## Проверки
- Дата из URL (rbc.ru/.../DD/MM/YYYY/..., rg.ru/YYYY/MM/DD/...) или из страницы источника.
- Не брать pro.rbc.ru и другие платные материалы.
- Не добавлять новости вне запрошенного периода.
